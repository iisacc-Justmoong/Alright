# Alright 실행·검증 계획

> Current behavior: version 0.5.0 creates PSD/AI at screen pixel dimensions and ends with Finder filename editing. See [Document creation](DocumentCreation.md).

2026-09-25 0.4.0 갱신: Alright 하위 메뉴에서 TXT·MD·RTF·PDF·JSON·CSV·HTML·SVG·PSD·AI 생성을 구현했다. 실제 Photoshop·Illustrator 열기와 6개 테스트 결과는 [문서 생성](DocumentCreation.md)에 기록한다. 복사·이동·출시 관문은 계속 후속 계획이다.

상태: 2026-09-20 작성. 아래 항목은 수행 계획이며 완료된 테스트 결과가 아니다.

2026-09-24 갱신: 실행 가능한 Hello World AppKit 호스트와 CMake/CTest 구성을 추가했다. 현재 구현·검증 범위는 [Hello World 기록](HelloWorld.md)에 있으며, 아래 Finder 확장 G0와 기능 인수 기준은 여전히 후속 계획이다.

2026-09-25 갱신: [Finder New Text](FinderNewText.md)에서 실제 빈 공간 메뉴 → 0바이트 TXT 생성 → 기본 편집기 열기, 호스트 종료 상태에서 자동 실행, 충돌 시 기존 파일 보존을 확인했다. 아래 G0의 핵심 수직 경로는 구현했지만, 권한 철회·Finder 재시작·다양한 저장소를 포함한 전체 관문과 A01–A15를 모두 통과한 것은 아니다.

2026-09-25 Swift 전환: macOS 전용 제품이며 호스트·Finder 확장·파일 생성·기능 테스트는 Swift 6이다. 앱 아이콘과 UI·메뉴에는 SF Symbols를 사용한다. 전환 후 실제 실행 검증은 [Finder New Text](FinderNewText.md)에 기록한다.

## 1. 첫 작업: 기술 실증 G0

목표는 **등록한 실제 로컬 폴더의 빈 공간 우클릭 → Alright → 새 TXT 생성 → Finder에서 확인**이다. 설정 화면의 시각적 완성도보다 이 경로를 먼저 증명한다.

1. 설치된 macOS·Xcode·SDK·서명 자격과 파일 시스템을 기록한다. 신규 구매 없이 사용 가능한 개발 환경을 확정한다.
2. 최소 AppKit 호스트와 Finder Sync 확장을 구성한다. 임시 테스트 폴더는 이 프로젝트의 `build/fixtures/` 안에 둔다.
3. 등록 폴더에서 항목 우클릭과 빈 공간 우클릭을 각각 확인한다. 메뉴 이벤트에서 선택 URL과 대상 URL을 정확히 얻는지 기록한다.
4. 호스트 앱 종료 상태에서 호출, 권한 전달, 북마크 재사용, 앱 재시작 후 접근을 검증한다. App Groups만으로 파일 권한을 얻었다고 판단하지 않는다.
5. 확장에서 호스트 실행부로 짧은 생성 요청을 넘겨 파일을 만든다. 파일명·내용·실제 생성 위치와 Finder 표시를 확인한다.
6. 확장 비활성화·권한 철회·Finder 재시작 시 복구 안내와 재활성화를 확인한다. 사용자 작업이 있는 Finder를 시험 목적으로 무조건 종료하지 않는다.

**통과 증거:** 실제 우클릭 화면, 생성된 파일 내용, 사용한 entitlements, 프로세스 간 요청·권한 흐름, 지원된 폴더 범위, 실패 로그이다. 컴파일 성공만으로 통과하지 않는다.

**실패 시 결정:** 빈 공간 메뉴나 권한 전달을 안정적으로 구현할 수 없으면 Services/Quick Actions에서 가능한 선택 항목 기능만 별도로 실증한다. 이 대안은 원래의 빈 공간 생성 요구를 충족하지 않으므로 제품 범위 변경으로 기록한다. 공식 API 범위에서 핵심 가치를 제공할 수 있는지 판단하기 전 대규모 기능 개발을 진행하지 않는다.

## 2. 단계별 산출물

| 단계 | 결과물 | 종료 기준 |
| --- | --- | --- |
| G0: 실증 | 최소 호스트·확장, 폴더 접근과 생성 증거 | 위 수직 경로가 실제 Finder에서 성공 |
| G1: 생성·경로 | 기본 3개 템플릿, 이름 규칙, 경로 출력 | 충돌·특수 문자·문맥 테스트와 실제 UI 통과 |
| G2: 정리 | 즐겨찾는 목적지, 복사·동일 볼륨 이동, 작업 내역 | 메타데이터 보존·부분 실패·복구 통과 |
| G3: 베타 | 설정·온보딩·접근성·진단, 지원표 | 도움 없는 설치·첫 작업을 관찰 검증 |
| G4: 상품화 | 사용자 템플릿·프리셋, 가격 실험, 배포 패키지 | 유료 가치 검증과 서명·공증·설치·실행 증거 |

개발 기간은 G0에서 환경과 기술 경로를 확인한 뒤 산정한다. 클라우드 지원·다른 볼륨 이동·Intel 호환 때문에 기본 로컬 폴더 출시까지 지연시키지 않되, 미지원 범위를 명확하게 표시한다.

## 3. 구현 파일 구조 초안

다음은 현재 구현 구조이다. New Text와 폴더 접근·요청 전달은 구현했으며 복사·이동·템플릿은 후속 범위이다.

```text
Alright/
  CMakeLists.txt
  src/
    core/               # Swift 파일 생성·경로 검증
    shared/             # Swift 권한 북마크·요청·SF Symbols
    app/                # AppKit 설정과 실행부
    finder_extension/   # Finder 메뉴와 요청 전달
  resources/            # 번들 정보·entitlements·번역·템플릿
  tests/                # 핵심 규칙과 OS 통합 검증
  docs/
  build/                # 모든 빌드·테스트 임시 파일·패키지
```

빌드 표준은 Swift 6과 CMake/Ninja/CTest이다. 모든 산출물은 `build/` 아래에 둔다.

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

위 명령은 현재 Swift 호스트·Finder 확장·회귀 테스트에 실행 가능하다. 앱은 `open build/bin/Alright.app`으로 실행한다. SDK 추출이 생기면 해당 SDK도 자체 `build/`에서 빌드·테스트·설치 소비자 검증을 수행한다. 소스 변경에는 관련 문서와 테스트 갱신이 함께 따른다.

| A10 | 앱/확장 중단과 동일 요청 재전달 | 저널 복구, 완료한 요청의 중복 수행 없음 |

| A13 | 작업 후 외부에서 파일 변경 | 되돌리기가 새 변경을 파괴하지 않음 |

| A15 | 접근성·언어 | 키보드만으로 설정 가능, VoiceOver 이름·상태 전달, 영어·한국어 잘림 없음 |

A14는 다른 볼륨 이동을 활성화할 때의 필수 관문이다. 복수 항목에는 각 항목의 결과를 검증하며 단일 성공 메시지로 실패를 숨기지 않는다. A03의 경로에 개행이 있으면 줄 기반 경로 복사의 모호성을 표시하거나 인코딩된 file URL 형식을 사용한다.

단위 테스트는 이름 정책·경로 출력·충돌 판단·복구 조건에 집중한다. 파일 I/O 통합 테스트는 실제 파일과 메타데이터를 비교한다. Finder 등록, 메뉴 노출, 권한 대화상자는 실제 네이티브 UI에서 검증한다. 목 객체 테스트만으로 OS 연동을 입증하지 않는다.

## 5. 호환성과 성능

초기 후보는 macOS 14 이상·Apple Silicon이다. 이는 확정 지원표가 아니다. 실제 검증한 OS·아키텍처만 지원으로 표시하며, 최소 버전과 출시 시점 최신 안정 버전에서 각각 확인한다. Intel 배포는 별도 빌드와 실기기 또는 적합한 검증 환경을 확보한 뒤 추가한다.

| 환경 | 최초 정책 | 공개 지원 전 확인 |
| --- | --- | --- |
| 사용자가 고른 로컬 APFS 폴더 | 첫 지원 대상 | 생성·복사·이동·메타데이터·되돌리기 |
| 바탕화면·문서 | 조건부 | 보호 폴더 권한, iCloud 설정 차이 |
| 외장 APFS·exFAT | 후속 | 해제·재연결, 파일명 규칙, 메타데이터 차이 |
| iCloud Drive | 후속 | 메뉴 노출, 내려받지 않은 파일, 파일 조정 |
| OneDrive·Dropbox | 후속 | 확장 공존, 공급자 권한·가용성 |
| SMB | 후속 | 끊김·지연·원자성·서버 파일명 제약 |

메뉴 생성 지연 목표는 로컬 테스트 폴더에서 p95 50ms 이하이다. 큰 파일 복사는 별도로 측정하며 이 수치에 포함하지 않는다. 확장 메뉴를 여는 동안 네트워크·디렉터리 재귀 탐색·파일 내용 해시를 수행하지 않는다. 유휴 상태에서는 주기적 폴링을 하지 않는다. 성능 목표는 아직 측정값이 아니며 장비·OS·선택 파일 수를 기록해 비교한다.

## 6. 배포와 운영

기존 인증 자격으로 가능한 경우 Developer ID 서명 → 공증 → 티켓 부착 → Gatekeeper 평가 → 개발 경로에 의존하지 않는 실제 앱 실행 → Finder 메뉴 호출까지 검증한다. 서명 검사 성공만으로 출시 완료라 하지 않는다. 현재 로컬 Developer ID 서명과 Finder 확장 등록·실행까지 검증했으며 공개 배포용 공증·패키지는 후속이다.

업데이트 검증에서는 기존 앱·설정·템플릿을 보존한다. 설정 스키마 이행 전 복구 가능한 사본을 유지하고, 확장과 앱 버전 불일치를 검출한다. 제거 방법은 확장 비활성화와 앱 제거를 설명하며 사용자 파일·템플릿 삭제를 기본으로 하지 않는다.

진단 화면은 “확장 꺼짐 / 폴더 미등록 / 접근 만료 / 미지원 위치 / 실행 실패”를 구분한다. 복구 안내와 경로를 가린 진단 내보내기를 먼저 제공하여 반복 CS 비용을 줄인다. 초기에는 별도 운영 서버·상시 분석 서비스·자동 결제 연동을 구축하지 않는다.
